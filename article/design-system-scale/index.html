سیستم طراحی وقتی تیم بزرگ می‌شود: از توکن تا مسئولیت کامپوننت

محمدعلی هاشمی
UI Designer
۲۲ دی ۱۴۰۴ زمان مطالعه: ۸ دقیقه

وقتی تیم بزرگ می‌شود، سلیقهٔ فردی سیستم را می‌شکند. توکن، مالکیت کامپوننت، مستند و نسخهٔ انتشار جلوی بدهی بصری و ناهماهنگی فرانت را می‌گیرند.

۱. توکن قبل از کامپوننت

رنگ، تایپ، فاصله و سایه را به‌صورت معنایی نام‌گذاری کنید (مثلاً color.text.muted) نه فقط palette.blue.500.

کامپوننت بدون مالک مثل API بدون SLA است — همه استفاده می‌کنند، کسی تعمیر نمی‌کند.

— محمدعلی هاشمی، UI Designer

۲. مالکیت روشن

هر پکیج UI مالک دیزاین و مالک مهندسی دارد. درخواست تغییر مسیر مشخص می‌خواهد.

۳. مستند زنده

استوری‌بوک یا معادل، حالت‌ها و ضدالگوها را کنار کد نگه دارید. PDF هفته‌ای یک‌بار می‌میرد.

حداقل مستند کامپوننت

  • کاربرد و غیرکاربرد
  • ویژگی‌ها و دسترس‌پذیری
  • نمونه کد

۴. نسخه و انتشار

SemVer، چنج‌لاگ و مسیر مهاجرت برای شکست‌های بصری اجباری است.

تغییر توکن را گران کنید

رنگ و فاصله را مستقیم در کامپوننت هاردکد نکنید. مسیر تغییر باید از توکن بگذرد تا یک اصلاح، همه‌جا بنشیند.

۵. بدهی بصری

هر اسپرینت سهمی برای حذف واریانت‌های یتیم بگذارید. سیستم بدون هرس جنگل می‌شود.

سیستم طراحی محصول داخلی تیم است. با همان جدیت محصول مشتری نسخه‌بندی و پشتیبانی‌اش کنید.
